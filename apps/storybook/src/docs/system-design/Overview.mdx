# System design

`designs/acceptance-gate.pen` is the source of truth for this design system — every token,
component, flow and decision starts there before it exists in code. The four boards below are
its current exported snapshot. This page narrates them; the other Docs pages are where the same
decisions are enforced or live-rendered — [Layering Rule](?path=/docs/docs-atomic-design-layering-rule--docs)
runs the tier rule as a lint, [Tokens](?path=/docs/docs-system-design-tokens--docs) renders the live token
sheet, [Diff Policy](?path=/docs/docs-qa-diff-policy--docs) and
[Visual Diff Workflow](?path=/docs/docs-qa-visual-diff-workflow--docs) cover the capture pipeline.
A board can drift from the code it described; a live-rendered page cannot. Where this page
found drift, it says so rather than repeating the board.

The normative inventory: every component named here is tier-assigned on this board, and issue
bodies transcribe it rather than re-deciding tiers downstream. Two things this board records
that no other Docs page does:

- **The layering enforcement mechanism** (which import direction is a lint error, not just a
  convention) lives on [Layering Rule](?path=/docs/docs-atomic-design-layering-rule--docs) — same `TIERS`
  array, read live rather than redrawn here.
- **The live token values** this board's raw `--c-*` palette resolves to as consumable
  `--color-*` roles are on [Tokens](?path=/docs/docs-system-design-tokens--docs), rendered straight out of
  `tokens.css` so they can't drift from what components actually use.

**Status, checked against the filesystem, not assumed from the board**: the board's "Named
candidates" row still lists five components as open — `Tag`, `PostMeta`, `Pagination`,
`SkipLink`, `EmptyState`. Four of those five exist as real components today
(`packages/ui/src/{atoms,molecules}/`); only `Pagination` remains unbuilt. The board _has_
been re-exported since (2026-08-17, for the addition below) — but that row wasn't redrawn,
so this page is still where the gap gets corrected until it is.

That 2026-08-17 revision added a second inventory to this board: the **Visual-diff console**
tier section — the NET-NEW components `apps/visual-diff-ui` needs, each tile carrying its
settled home. The generic primitives (`BucketChip`, `TriStateCheckbox`, `SegmentedControl`,
`Thumbnail`, and the extracted `Table` and `Dialog`) enter `packages/ui` and its capture
matrix; everything that knows the visual-diff domain stays an app-local composition. Board 04
narrates the pages they compose.

## Board 02 — Flows & decisions

<img
  src="/designs/flows-decisions.png"
  alt="Flows & Decisions board"
  style={{ width: '100%' }}
/>

### Reader flows (F1–F3)

Three entry-point flows, each with real coverage at a different layer today:

- **F1 (Index → Post)** — click a card, land on the article. Covered end-to-end: the "Read a
  full article" scenario in `apps/e2e/features/blog.feature` opens the first article from the
  index and asserts the body renders.
- **F2 (Tag → Filtered index)** — any tag pill routes to `/tags/[tag]`, same index template,
  `EmptyState` when a tag has no posts. **No e2e scenario covers this yet** — it's asserted only
  by what the route itself renders, not by a scripted journey.
- **F3 (Theme toggle)** — flips `[data-theme]` on `<html>`, persisted to `localStorage`, a
  pre-hydration script kills the flash. Covered by unit tests
  (`ThemeToggle.test.tsx`, `first-paint.test.ts` in `apps/blog/__tests__/`), not e2e — the
  mechanism is fully exercised, the user-visible click-and-see-it-change journey isn't scripted.

Why the flows are written as `.feature` files at all — and why a step definition is allowed to
change when the markup does, while the scenario above it is not — is the argument in
[Cypress and Gherkin: specs an agent can maintain](https://acceptance-gate-blog.vercel.app/blog/gherkin-specs-that-survive).

### Design decisions (D1–D2)

Both of these are recorded twice by design: narratively on the board, and as the literal
rationale a maintainer reads while editing the token sheet. The second one is authoritative —
quoted here rather than restated:

- **D1 (Typography)** — `packages/ui/src/tokens.css`: _"Light is editorial parchment: cream
  ground, terracotta accent, warm ink."_ Fraunces for display, Atkinson Hyperlegible for body
  (chosen for legibility — it backs the repo's own accessibility story), JetBrains Mono for
  code and metadata. All three self-hosted as woff2; see `fonts.css` for why the format and the
  `font-display: block` rule are load-bearing for capture determinism, not just performance.
- **D2 (Dark mode)** — `packages/ui/src/tokens.css`: _"Dark is deliberately its own personality:
  terminal lime on green-tinted black... Light stays the editorial parchment theme — the two
  must never be byte-identical, and the differ proves it."_ Only the semantic `--color-*` roles
  remap under `[data-theme='dark']`; the raw `--c-*` scale never changes shape between themes.
  The switch mechanism itself — `[data-theme]`, never a media query — is the same one
  [Diff Policy](?path=/docs/docs-qa-diff-policy--docs) and
  [Visual Diff Workflow](?path=/docs/docs-qa-visual-diff-workflow--docs) depend on: Storybook's
  decorator and the differ's capture URL both set the attribute explicitly, which a live
  `prefers-color-scheme` query would leave both blind to.

Since 2026-08-17 the board also carries a second, visual-diff-scoped set (ink-black chips,
where the blog flows wear terracotta): flows **F1–F4** — the review loop, launching a
comparison, meeting an `a11y` failure, accepting baselines — and decisions **D1–D3** — one
job at a time, nothing deleted implicitly, and accept is container-bound and atomic, with
the UI supplying the host guard the CLI deliberately lacks. They belong to the pages on
Board 04, and are narrated there.

## Board 03 — Pages: the capture matrix

<img
  src="/designs/pages.png"
  alt="Pages — the capture matrix board"
  style={{ width: '100%' }}
/>

This board describes a **page-level** capture matrix — the three route types (blog index, post,
tag), each in all four variants the differ's own policy already names (desktop/mobile ×
light/dark). That's a different matrix from the one on
[Diff Policy](?path=/docs/docs-qa-diff-policy--docs): this one is routes, that one is Storybook
stories. `packages/visual-diff` only ever captures stories today — there is no page-level
pixel-diff in this repo yet. `apps/e2e/features/blog.feature` covers the same three page types
functionally (the index lists articles, an article opens and renders, drafts stay hidden), but
none of that asserts appearance.

This board is recording intent, not shipped behavior — worth being direct about, since the
image alone doesn't say so. It maps onto the distinction
[Visual regression with agents](https://acceptance-gate-blog.vercel.app/blog/visual-regression-with-agents)
draws between a small, zero-tolerance **contract set** and a wider **sweep** that exists to make
change visible rather than to gate a merge: a page-level capture across three routes × four
variants is shaped exactly like that wide sweep, not like the tight, gated set that post argues
for. If this ever gets built, that's the distinction to build it against — not a straight
port of the story-level matrix to routes.

## Board 04 — Pages: the visual-diff console

<img
  src="/designs/visual-diff-pages.png"
  alt="Pages — visual-diff console board"
  style={{ width: '100%' }}
/>

The design for `apps/visual-diff-ui` — a console over the capture pipeline that
[Diff Policy](?path=/docs/docs-qa-diff-policy--docs) and
[Visual Diff Workflow](?path=/docs/docs-qa-visual-diff-workflow--docs) document. Two routes,
`/` and `/report/[id]`, drawn in the same four variants as Board 03, plus the comparison
modal in both of its presentations: a floating overlay on desktop, and a full-screen bottom
sheet on mobile with every control moved into thumb reach and `actual size` yielding to
native pinch-zoom.

Like Board 03, this is **intent, not shipped behavior** — no `apps/visual-diff-ui` workspace
exists yet. Unlike Board 03, it is drawn as a buildable spec, and its structural decisions
are already settled rather than deferred:

- **Component homes are decided on Board 01.** The generic primitives enter `packages/ui`
  and its capture matrix; everything that knows about a comparison's data — the story card,
  the three-up viewer, the tables, the modal's contents — stays an app-local composition.
  Domain semantics never leak into the design system, and the pixel budget grows by
  primitives, not organisms.
- **The `a11y` bucket outranks the pixel verdict.** That rule is already
  `packages/visual-diff`'s — `a11y` is a first-class bucket that never folds into
  `changed` or `unchanged`. This board gives it the treatment a pixel differ can't: the
  report page leads with the accessibility section whenever it is non-empty, an `a11y`
  variant shows its violation list where the diff image would be, and reviewing it never
  clears it — only a fix does.
- **Accepting baselines is container-bound, and the UI is the guard.** The CLI's `accept`
  deliberately carries no host guard; the console's accept mode refuses to offer a run
  button unless the runner matches the pinned Playwright image, degrading to a copyable
  `docker run` command below that bar.

The board's mockups resolve their colors through `.pen` variables that mirror the
`success`/`warning`/`danger` role pairs on
[Tokens](?path=/docs/docs-system-design-tokens--docs) — same values, both themes — so the
drawings can't quietly drift from the sheet the components will actually consume.
